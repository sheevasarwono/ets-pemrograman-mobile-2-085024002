1. MODEL DATA DAN NULL SAFETY (15 Poin)

1.1 Konsep Null Safety di Dart

Dart 2.12+ secara default menerapkan Sound Null Safety. Sistem tipe Dart membedakan secara ketat antara tipe yang tidak dapat menerima nilai null (*non-nullable*) dan tipe yang diperbolehkan bernilai null (*nullable*). Dengan sound null safety, kompilator dapat menjamin bahwa variabel non-nullable tidak akan pernah bernilai null saat aplikasi berjalan (menghilangkan potensi NoSuchMethodError atau NullPointerException).

1.2 Perbedaan String dan String?

  • String (Non-nullable): Wajib selalu memegang referensi ke objek teks nyata. Kompilator menolak pemberian nilai null baik saat inisialisasi maupun penugasan ulang. Digunakan untuk atribut yang mutlak harus ada, seperti title dan author.
  • String? (Nullable): Diizinkan memegang referensi string atau bernilai null. Tanda tanya (?) menginstruksikan kompilator bahwa atribut tersebut bersifat opsional, seperti pada properti description.

1.3 Parameter required

Kata kunci required disematkan pada *named parameters* dalam konstruktor kelas untuk menandakan bahwa pemanggil konstruktor wajib menyediakan nilai pada argumen tersebut saat instansiasi objek. Jika diabaikan oleh pemanggil, kesalahan kompilasi (*compile-time error*) akan langsung dimunculkan.

1.4 Strategi Penanganan Deskripsi Null

Untuk menangani deskripsi null secara informatif, kelas Book mengimplementasikan getter aman:

class Book {
  final String id;
  final String title;
  final String author;
  final int year;
  final String? description;

  const Book({
    required this.id,
    required this.title,
    required this.author,
    required this.year,
    this.description,
  });

  bool get hasDescription =>
      description != null && description!.trim().isNotEmpty;

  String get displayDescription =>
      hasDescription ? description! : 'Deskripsi belum tersedia untuk buku ini.';
}

2.1 Perbedaan Responsive UI dan Adaptive UI

Karakteristik Responsive UI Adaptive UI
Fokus Penyesuaian Ukuran fisik layar, rasio aspek, lebar-tinggi piksel, dan orientasi layar (Portrait vs Landscape). Sistem operasi atau platform target (Android, iOS, macOS, Windows, Web) serta gaya interaksinya.

Komponen Flutter LayoutBuilder, MediaQuery, Expanded, Flexible, GridView. Theme.of(context).platform, dialog adaptif (showAdaptiveDialog), tombol Cupertino vs Material.

2.2 Penerapan Responsive UI dengan LayoutBuilder & MediaQuery

Aplikasi menggunakan LayoutBuilder untuk membaca batasan lebar (constraints.maxWidth) dan MediaQuery untuk mendeteksi orientasi perangkat:

return LayoutBuilder(
  builder: (context, constraints) {
    // Breakpoint: Layar lebar jika lebar >= 650px atau landscape
    final isWideScreen = constraints.maxWidth >= 650 || 
        (isLandscape && constraints.maxWidth >= 550);

    return CustomScrollView(
      slivers: [
        SliverToBoxAdapter(child: OwnerHeader(isWideScreen: isWideScreen)),
        if (isWideScreen)
          SliverGrid(
            gridDelegate: const SliverGridDelegateWithFixedCrossAxisCount(
              crossAxisCount: 2,
              crossAxisSpacing: 12,
              mainAxisSpacing: 12,
              mainAxisExtent: 310,
            ),
            delegate: SliverChildBuilderDelegate(
              (context, index) => BookCard(book: books[index]),
              childCount: books.length,
            ),
          )
        else
          SliverList(
            delegate: SliverChildBuilderDelegate(
              (context, index) => BookCard(book: books[index]),
              childCount: books.length,
            ),
          ),
      ],
    );
  },
);

Hasilnya:
• Pada smartphone vertikal (lebar < 650px): Aplikasi menggunakan tata letak SliverList 1-kolom.
• Pada tablet/desktop/landscape (lebar ≥ 650px): Aplikasi otomatis menyusun kartu dalam SliverGrid 2-kolom dengan proporsi yang simetris dan lega.

2.3 Contoh Rancangan Adaptive UI

Untuk menyempurnakan aspek adaptive di masa mendatang, aplikasi dapat merancang:

  • Peralihan otomatis antara AlertDialog (Android) dan CupertinoAlertDialog (iOS) saat konfirmasi aksi.

3.2 Implementasi Provider

// 1. nameProvider & npmProvider (Identitas)
final nameProvider = Provider<String>((ref) => StudentInfo.defaultName);
final npmProvider = Provider<String>((ref) => StudentInfo.defaultNpm);

// 2. booksProvider (Koleksi Buku)
final booksProvider = Provider<List<Book>>((ref) => _initialBooks);

// 3. infoProvider (Derived State menggabungkan nama dan jumlah buku)
final infoProvider = Provider<String>((ref) {
  final name = ref.watch(nameProvider);
  final books = ref.watch(booksProvider);
  return 'Nama saya $name, saya memiliki ${books.length} buku.';
});

// 4. expandedBookIdsProvider (State Notifier untuk Toggle Deskripsi)
class ExpandedBooksNotifier extends Notifier<Set<String>> {
  @override
  Set<String> build() => <String>{};

  void toggle(String bookId) {
    if (state.contains(bookId)) {
      state = {...state}..remove(bookId);
    } else {
      state = {...state, bookId};
    }
  }

  bool isExpanded(String bookId) => state.contains(bookId);
}

final expandedBookIdsProvider =
    NotifierProvider<ExpandedBooksNotifier, Set<String>>(
  ExpandedBooksNotifier.new,
);

3.3 Perbandingan Provider, FutureProvider, dan StreamProvider

Tipe Provider Mekanisme Kerja Nilai yang Dikeluarkan Kapan Digunakan?
Provider Sinkron murni (*synchronous*). Mengembalikan data tetap atau hasil komputasi antar-provider. T (Objek langsung) Data statis, service/repository instance, derived state (seperti infoProvider).
FutureProvider Asinkron 1 kali (*single asynchronous execution*). Otomatis mengelola siklus loading, success, error. AsyncValue<T> Mengambil data dari REST API HTTP sekali saat halaman dibuka, membaca database SQLite lokal.
StreamProvider Asinkron berkelanjutan (*continuous asynchronous events*). Mendengarkan aliran data secara real-time. AsyncValue<T> Aplikasi chat real-time (WebSocket), Firestore stream, sensor GPS/akselerometer berkala.

4. ANIMASI SEDERHANA (IMPLICIT ANIMATION) (10 Poin)

4.1 Penggunaan Implicit Animation

Pada widget BookCard, antarmuka mengimplementasikan animasi implisit untuk memberikan respons visual yang memanjakan pengguna saat tombol ekspansi ditekan:

  • AnimatedContainer: Menganimasikan perubahan dimensi tinggi, padding internal dari EdgeInsets.zero ke EdgeInsets.all(12), dan perubahan warna latar belakang kotak deskripsi selama 300 milidetik dengan kurva Curves.easeInOut.

5.2 Evaluasi Hubungan Pola MVVM (Model-View-ViewModel)

  • Model (models/book.dart): Merepresentasikan data murni dan aturan domain. Independen dari UI dan Riverpod.
  • View (screens/ & widgets/): Murni bertugas merender UI dan mendengarkan perubahan data melalui ref.watch(). Tidak ada logika bisnis di dalam View.
  • ViewModel (providers/): Riverpod providers mengabstraksikan dan menyajikan state ke View. Aksi pengguna dialirkan ke Notifier melalui ref.read(...).
  • Bagian yang Belum Ada: Lapisan Repository dan Data Source (karena tugas ini menggunakan data statis in-memory tanpa database/API eksternal).
